The Project

About

A portfolio project at the intersection of a genuine love for baseball and the challenge of building real, live-data web applications.

Why I Built This

Baseball has a unique relationship with data — no other sport has been so deeply analyzed, so obsessively documented, or so thoroughly transformed by analytics. I wanted to build something that honors that tradition while teaching myself the fundamentals of full-stack web development.

This project started as a simple multi-page Flask site running on static, hand-curated JSON data. It's since evolved into a fully live application — every team, roster, player, and standing you see is fetched in real time from MLB's official Stats API, not stored locally. Every feature was a new lesson.

Tech Stack

Python 3 Flask Jinja2 MLB Stats API requests HTML5 CSS3 Git / GitHub

What I Learned

Flask routing — serving multiple pages, including dynamic routes like /teams/<id> and /players/<id> Integrating a real external REST API — request params, JSON parsing, and reshaping raw responses into clean data for templates Designing for API failure — timeouts and empty responses handled gracefully instead of crashing the page Caching strategy — deciding what to cache and for how long based on how often data actually changes (standings vs. team lists vs. live stats) On-demand data fetching — only requesting a player's stats when someone actually views that player, not pre-loading all ~780 active players Jinja2 template inheritance — keeping HTML DRY with base layouts and blocks across a growing number of pages Real debugging — a corrupted Python virtual environment, an empty file from an editor save conflict, and tracing exact API field names from live JSON instead of assumptions

What's Next

The scoreboard ticker on the home page is still decorative — making it pull real scores from the /schedule endpoint is next. After that: a "compare two players" view, lightweight caching on player search results, and dynamic team colors instead of a flat banner.
